# study-quiz — тренажёр для запоминания из любых материалов

Ты превращаешь учебный материал в тренажёр: вопросы, шпаргалки, флэшкарты и карту понятий. **Цель — запомнить теорию, а не проверить человека.** Это главная мысль, все правила вытекают из неё.

Файлы скилла (пути от папки, где лежит этот SKILL.md; обычно `~/.claude/skills/study-quiz/`):
- `RULES.md` — правила составления вопросов, понятий и шпаргалок. **Прочитай целиком до начала работы** и соблюдай всё.
- `docs/FORMAT.md` — формат файлов: все 10 типов вопросов, понятия, связи, шпаргалки, файл-часть для вставки урока.
- `assets/trainer/` — шаблон тренажёра (с примером-образцом на теме «Как работает память»).
- `assets/cloud/`, `docs/CLOUD.md` — необязательная облачная копия для телефона с общим прогрессом.
- `scripts/` — инструменты. Все запускаются **из папки проекта** (где лежит `trainer/`):

| скрипт | что делает |
|---|---|
| `extract_html.py` | текст сохранённых HTML-страниц → `notes/*.md`, проверка, что страница сохранилась целиком |
| `sync.py [--lock]` | что изменилось в `notes/` по сравнению с тренажёром: NEW / CHANGED / REMOVED |
| `add_topic.js part.js [--replace] [--dry]` | вставить новый урок или заменить переписанный |
| `remove_topic.js <id урока> [--dry]` | убрать урок отовсюду (всё убранное — в `archive/removed/`) |
| `patch_questions.js patch.json` | поправить поля вопросов по id: `{ "id": { "поле": значение \| null } }` |
| `delete_questions.js "причина" id…` | удалить отдельные вопросы |
| `validate.js` | структура вопросов, понятий, связей, шпаргалок |
| `dumb_check.js --list` | признаки тупых вопросов |
| `terms.py` | все ли термины из конспектов попали в вопросы |
| `e2e.py`, `e2e_study.py` | автотесты в headless-Chrome |
| `screens.py` | скриншоты экранов для проверки глазами |
| `deploy.sh` | выкладка облачной копии (если настроена) |

Дальше `S` — папка `scripts/` скилла, например `S=~/.claude/skills/study-quiz/scripts`.

## 1. Определи проект

- **В папке уже есть `trainer/index.html`** — это готовый тренажёр: добавляй в него. Если в папке есть `CLAUDE.md` или свои правила (например, `RULES.md`), прочитай их: правила пользователя важнее правил скилла.
- **Тренажёра нет** — создай проект:
  1. `cp -r <скилл>/assets/trainer ./trainer`.
  2. В `trainer/config.js` впиши `title` (название в шапке), `subtitle` (крупный заголовок, обычно название курса) и **уникальный** `key`, например `trainer-biology-2026`. Все страницы, открытые через `file://`, делят одно хранилище браузера: без уникального ключа прогресс разных тренажёров смешается.
  3. Заведи папки `sources/` (исходники как есть) и `notes/` (чистый текст по урокам).
  4. Пример (`quiz-data-example.js`, `study-example.js`) оставь как образец формата, пока пишешь первую тему, потом удали файлы и их строки `<script>` из `index.html`.
  5. Предложи пользователю завести `CLAUDE.md` в папке проекта: кратко что за курс и какие префиксы id заняты — это ускорит следующие сессии.

## 2. Материал → текст в `notes/<урок>.md`

Для каждого урока нужен файл с полным текстом. Имя файла = полное название урока (оно же поле `lesson` в тренажёре; «:» и «/» в имени заменяются на «_»). Термины выделяй `**жирным**`, схемы отмечай строкой `[IMG путь]`.

| Что прислали | Как читать |
|---|---|
| Фото / скан рукописи, скриншоты | Read по картинке, перепиши текст. Неразборчивое помечай `[?]` и спроси пользователя. Схемы и таблицы опиши текстом, разборчивые сохрани как картинку. |
| PDF | Read с `pages` (не больше 20 страниц за вызов) или навык `pdf`. Нужные схемы вырежи. |
| docx / pptx | Навыки `docx` / `pptx` или `textutil -convert txt` (macOS), `pandoc`. |
| Сохранённые HTML-страницы | `python3 $S/extract_html.py sources/ "Урок 1" "Урок 2" …` (список — из оглавления курса). Покажи таблицу «урок → что не так» и попроси пересохранить только битые. |
| Ссылка на открытую страницу (статья, документация) | WebFetch. |
| Ссылка на платный курс / закрытую платформу | **Не заходи и не парси сам.** Условия таких платформ обычно запрещают автоматический сбор, пользователя могут отключить. Попроси сохранить страницы вручную: открыть урок, дождаться загрузки, прокрутить до конца, «Сохранить как → Веб-страница, полностью» в `sources/`. Или прислать текст. |
| Просто текст в чате | Сохрани как есть. |

Если прислали **список уроков** (скриншот оглавления), сверь с ним, что всё на месте, и скажи, чего не хватает.

## 3. Что поменялось (для существующего тренажёра)

```bash
python3 $S/sync.py
```
- 🆕 **NEW** — конспект есть, урока нет → шаг 4.
- ✏️ **CHANGED** — текст конспекта изменился после последней сборки → посмотри `diff` (скрипт печатает команду). Мелкие правки — точечно через `patch_questions.js`. Существенные — собери часть заново: вопросы на неизменившуюся теорию оставь **с прежними id** (так сохранится прогресс), новое добавь, устаревшее убери, вставь через `add_topic.js --replace`.
- 🗑 **REMOVED** — урок есть, конспекта нет → `node $S/remove_topic.js <id> --dry`, потом без `--dry`. После удаления проверь шпаргалки и связи соседних уроков. Если пропало больше половины уроков темы — сначала спроси пользователя, не случайно ли удалены файлы.
- **Переименование:** REMOVED и NEW с почти одинаковыми названиями — скорее всего один урок. Сверь тексты; если это он, обработай как CHANGED с тем же id урока и новым `lesson`.

## 4. Составь урок

1. Прочитай урок **целиком**, включая схемы: в них часто теория, которой нет в тексте.
2. **Сначала выпиши каркас:** понятия (определения дословно), списки со всеми пунктами, классификации, этапы, формулы, сравнения. Разбей на микротемы, 2–4 на урок.
3. По каркасу собери **файл-часть** (формат — `docs/FORMAT.md`, раздел «Файл-часть»): урок, микротемы, вопросы, понятия, связи, шпаргалка, связи с другими темами. Коротко о главном (подробно — `RULES.md`):
   - ~10–20 вопросов на урок, 3–5 на микротему; определения упаковывай в «соедини» на 3–5 пар, списки — в «выбери все» + «перечисли»;
   - определения и термины — **словами материала**;
   - **никаких кейсов и расчётов**, вопросов о курсе и героях примеров, тупых вопросов;
   - развёрнутый разбор и подсказка-наводка у всех, кроме «вспомни»;
   - в каждой микротеме со свободными ответами — минимум 2 простых вопроса на те же понятия;
   - сравнения и схемы из материала — типами `table` и `frame`;
   - 4–10 понятий на урок, шпаргалка на 3–5 блоков, минимум одна связь с понятием другого урока.
4. Новая тема — новый `group` (`id: "g-<slug>"`), `slug` для файлов и **новый префикс id** (одна-две латинские буквы, не занятые в `trainer/quiz-data*.js`).
5. Картинки: `sips -Z 1400 "<исходник>" --out "trainer/img/<префикс>-<имя>.png"` (не macOS — `magick … -resize 1400x1400\>`).
6. Вставь: `node $S/add_topic.js part.js --dry`, потом без `--dry`.
7. Посмотри, не появились ли у старых уроков связи с новыми понятиями — допиши их в `trainer/study-links.js`.

**Большой объём.** Если уроков больше 6–8, раздай работу помощникам (Agent): **один помощник на тему, 4–9 уроков, без вложенных помощников**. Для генерации подойдёт модель попроще, качество проверяй сама. Каждому передай: путь к `RULES.md` и `docs/FORMAT.md` (прочитать целиком), его уроки в `notes/` и картинки, пример `assets/trainer/quiz-data-example.js`, его префикс id и путь для файла-части. Помощник сам проверяет, что его часть загружается: `node -e 'require("./part.js")'`.

## 5. Проверь (всё обязательно)

```bash
node $S/validate.js            # 0 ошибок; предупреждения про микротемы тоже исправь
node $S/dumb_check.js --list   # длинный правильный вариант, упоминания курса и героев, расчёты, дубли
python3 $S/terms.py            # пропущенные термины (часть ложные — проверь глазами)
python3 $S/e2e.py              # марафон по всем вопросам: порядок, без зависаний
python3 $S/e2e_study.py        # «На сегодня», шпаргалки, карточки, карта
python3 $S/screens.py          # скриншоты в /tmp/study-quiz-screens — посмотри новую шпаргалку глазами
```

Потом сама пройдись по новым вопросам: нет ли кейсов, расчётов, вопросов про курс; не выдают ли ответ подсказки и картинки; не длиннее ли правильный вариант остальных.

Для браузерных тестов нужен Chrome (Google Chrome, Chromium или Playwright). Путь можно задать переменной `CHROME`.

Когда всё чисто: `python3 $S/sync.py --lock` — запомнить состояние, чтобы в следующий раз увидеть CHANGED. Если настроено облако — `bash $S/deploy.sh`.

## 6. Отчитайся коротко

- сколько уроков, вопросов, понятий и шпаргалок добавлено, изменено, убрано;
- какие картинки взяты;
- чего не хватает в исходниках и что пересохранить;
- найденные ошибки и противоречия в материале и какая версия использована;
- как открыть: двойной клик по `trainer/index.html`.

## Устный экзамен

Пользователь пишет «проверь меня по <теме>» (можно приложить экспорт прогресса — кнопка «Сохранить прогресс в файл»).
1. Если есть экспорт — выбери слабые места: вопросы и карточки с `last: 0`, карточки с `box ≤ 2`, микротемы с ошибками. Если нет — бери понятия темы вразброс, упор на ключевые.
2. Задавай **по одному** 8–10 вопросов «объясни своими словами»: что такое X, чем X отличается от Y, из чего состоит, как связаны (опора — `concepts` и `links`). Только теория, без кейсов и расчётов.
3. На каждый ответ — коротко: что верно, что упущено, эталон из `def`. Не хвали за пустое.
4. В конце — итог: что знает, что повторить. Запиши в `exams/<дата>-<тема>.md`.
5. Сделай `exams/<дата>-import.json`: `{ "merge": true, "reset": { "q": [id вопросов], "cards": [id понятий] } }` и скажи загрузить его кнопкой «Загрузить из файла» — упущенное вернётся в «На сегодня».

## Как устроен тренажёр

Если просят поменять интерфейс: логика и экраны главной, «Своего теста», теста и итогов — `trainer/index.html`; шпаргалки, карточки и карта — `trainer/study.js`; интервальное повторение — `trainer/srs.js`.

- **Главная:** «На сегодня» (одна кнопка) → «Уроки» (урок открывается шпаргалкой: тест по уроку, карточки, ошибки, микротемы) и «Карта курса» → «Свой тест» (любые уроки, всё / новое / ошибки, длина 20 / 40 / 80 / все, история).
- **Порядок в тесте** (`buildOrder`): три фазы — простые → структура → свободный ответ; «верно/неверно» по микротеме только после её определения; типы не идут подряд.
- **Состав теста** (`pickSubset`): ошибки → новые → давно повторённые, микротемы по кругу, сложные — только после простого вопроса той же микротемы.
- **«На сегодня»** (`srs.js`): лестница 1 → 3 → 7 → 16 → 35 → 80 дней; ~25 вопросов в день пополам повторения и новые (новые — попеременно с начала курса и с конца); карточки — в конце сессии.
- **Прогресс** — `localStorage` под ключом `TRAINER.key` из `config.js`; экспорт и импорт в файл на главной.
- После правок интерфейса: `e2e.py`, `e2e_study.py` и скриншоты. Внешний шрифт в тестовых копиях скрипты отключают сами.

## Экономия токенов

- Сначала собери все требования пользователя, потом делай **один проход**. Не переписывай весь банк после каждого замечания.
- Файлы вопросов быстро становятся большими. Не читай их целиком и не переписывай руками: меняй точечно скриптами по id.
- Материал читай один раз: сначала в `notes/`, дальше работай с `notes/`. Картинки смотри только для уроков, которые разбираешь сейчас.
- Каждое замечание пользователя — правило на будущее: допиши его в правила проекта и примени ко всем темам (`RULES.md` §11).
